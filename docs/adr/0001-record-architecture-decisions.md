# ADR 0001: Record architecture decisions and Phase 1 tooling

- Status: Accepted
- Date: 2026-09-29

## Context

KnowVault is built by one developer as a portfolio project. Decisions need to be visible to
reviewers and easy to revisit. `docs/ARCHITECTURE.md` describes the target architecture; it
leaves several tooling choices open (§19).

## Decision

- Significant, hard-to-reverse decisions are recorded as short ADRs in `docs/adr/`, numbered
  sequentially. `docs/ARCHITECTURE.md` is updated to stay consistent with them.
- Code, comments, commit messages, README and ADRs are written in English (D1).
- Backend: Python 3.13, FastAPI, SQLAlchemy 2 (async, asyncpg), Alembic, Pydantic Settings.
  Tooling: `uv`, `ruff` (lint + format), `mypy --strict` (D15), `import-linter`, `pytest`.
- Frontend: Next.js 16 (App Router), TypeScript (strict), Tailwind CSS 4, TanStack Query,
  `openapi-fetch` with types generated by `openapi-typescript`. Tooling: ESLint, Vitest,
  Testing Library.
- **npm instead of pnpm.** npm ships with Node, so contributors need one tool fewer. This
  reverses the pnpm recommendation in the architecture document.
- The OpenAPI schema (`apps/api/openapi.json`) and the generated client types
  (`apps/web/src/lib/api/schema.ts`) are committed. CI regenerates both and fails on drift.

## Consequences

- The API contract is reviewed like code; a backend change that breaks the frontend's types
  shows up in the pull request.
- Contributors need `uv` and Node 22 to work outside Docker.
